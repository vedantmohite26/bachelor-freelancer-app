## 2026-11-21 - Fixing Firestore Stream Listener Leak in WalletService
**Learning:** Firestore snapshot listeners (`snapshots().listen()`) that are not explicitly tracked and cancelled across logins, logouts, or screen re-mounts lead to critical memory leaks, redundant state updates (by firing duplicate `notifyListeners()`), and inflated database read costs. Consolidating the stream listener by tracking the active `StreamSubscription` and target `userId`, early-returning on duplicate calls, and implementing clean disposal prevents this resource drain.
**Action:** Always store the returned `StreamSubscription` when registering real-time Firestore listeners in Flutter services. Prior to establishing a new snapshot stream, check if it's already active for the same parameters, cancel any existing active subscription, and implement `dispose()` to clean it up.
