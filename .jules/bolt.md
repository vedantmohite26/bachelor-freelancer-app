## 2026-11-20 - [Deduplicating Concurrent Firestore Reads with In-Memory Future Caching]
**Learning:** In highly concurrent Flutter UI list environments (e.g., reviews list rendering multiple `ReviewCard` elements simultaneously), multiple widgets can concurrently issue Firestore requests for the same referenced profile. Caching the raw fetched data is insufficient to prevent redundant simultaneous network calls because subsequent requests are initiated before the first call resolves. Caching the `Future` object itself acts as a single-source-of-truth task, allowing all concurrent and subsequent callers to share the exact same active or resolved request, eliminating the N+1 read overhead. Synchronously registering an error handler on the `Future` and invalidating on failures ensures zero stale or broken cached states.
**Action:** Always store the `Future` itself in the service's in-memory cache, deep-copy resolving data using `Map<String, dynamic>.from(data)` to prevent shared reference mutation bugs, and clear the cached future on any profile-altering mutations.
