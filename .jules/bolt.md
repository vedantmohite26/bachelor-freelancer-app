## 2026-06-25 - Future-based In-Memory Caching for Firestore Reads in Flutter
**Learning:** Storing the `Future` itself rather than its resolved value in a service-level caching map (`Map<String, Future<Map<String, dynamic>?>>`) enables concurrent, duplicate read requests (such as multiple parallel `FutureBuilder` instances in scrolled list items) to share the exact same Firestore call instance. This successfully avoids redundant simultaneous network requests. Additionally, returning deep copies of the cached data is crucial to prevent individual UI widgets from mutating the shared internal cache.
**Action:** Always store the `Future` object in the service cache, and chain `.then((data) => data != null ? Map<String, dynamic>.from(data) : null)` when retrieving it to ensure deep copies are returned. Always perform static cache invalidation AFTER the asynchronous database update succeeds.
